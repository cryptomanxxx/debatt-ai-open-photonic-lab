# Selective CI v2

The PR workflow compares the experiment registry at the git merge base against the checked-out registry using the same base as the changed-file diff. Added or modified entries select their own experiments, including heavy entries. Unchanged entries are not selected solely because the registry was edited. Formatting, documentation and entry ordering alone do not trigger simulations. Changed scripts and declared dependencies still select their consumers. The default lock selects default-lock users and explicit dependency matches; a custom lock selects its users. Other shared dependencies select all experiments. Shared policy changes select all experiments. Registry removal, other global policy changes and changes to CI machinery conservatively select all non-heavy experiments, plus any directly affected heavy experiments. Without a baseline, registry edits retain conservative non-heavy regression. A missing or unreadable baseline in the PR workflow fails selection rather than silently skipping checks.

The registry consistency check, selector tests and bundle tests still run. All selected experiment jobs and combined artifact checks are unchanged. PR #55 itself changes CI infrastructure and therefore intentionally triggers regression of all non-heavy experiments, including MOD-007. Future registry-only additions no longer do so. Full regression remains available via Actions → Experiments → Run workflow → experiments: `all` (includes heavy experiments). No scheduled run is enabled; this avoids unrequested recurring compute usage.
