# Scientific artifact archival

The existing Experiments workflow produces individual CI artifacts and a combined bundle. The new Archive scientific experiment workflow archives one explicitly selected original artifact without rerunning a simulation or copying CSV through chat.

## Automatic mode (opt-in public profiles)

A merged same-repository PR targeting main triggers trusted main archive code via pull_request_target closed. Archive branches are excluded. Discovery matches the exact merged PR head to the latest Experiments PR run; when run PR associations are present they must include the selected PR number. Missing associations are permitted only with mandatory historical checkout log binding to the selected PR number before publication. Explicit recovery fails rather than silently succeeding if no candidate is found. Discovery reports run and artifact counts. It requires success and selects a registered, unexpired artifact with a reviewed file profile in tools/archive-public-profiles.json. It skips existing archive directories/branches and fails closed on ambiguity or multiple pending artifacts. No source PR code is checked out or executed. The existing byte/provenance checks remain mandatory, including ancestry and exact executed registry entry. The bot only creates a review PR; it does not merge or approve. GitHub CI approval and an authenticated Codex request remains necessary.

Initially only OPA-G-004A synthetic public outputs are opted in. Adding another experiment requires review of its data/publication scope, exact filenames and environment outputs in the public profile file. Do not automatically publish arbitrary ZIP contents. Profiles are explicit publication policy, not secret scanning. If output contents change unexpectedly the exact allowlist check fails. For recovery of a previously merged eligible PR, manually dispatch with only merged_pr and confirm_public_archive; do not enter the other identifiers. Existing explicit manual mode remains for unprofiled experiments. Automatic mode has been live-tested on G-004A/B/B2/C1. Multiple eligible artifacts require manual selection in this version.

### Regression runs versus new scientific evidence

PR #291 (analysis of already archived G-004C1) triggered a valid experiment regression because the research Markdown was a registered dependency. Its subsequent archive job failed on the unexpected README.md in the ZIP (run 45865265336). The original archive from PR #290 was unaffected.

Automatic discovery now checks the complete paginated merged-PR file list, including old and new rename paths. For each profile it requires a changed executable or non-documentation dependency (including data or lock inputs), or a semantic change to that experiment's registry entry. Markdown and reStructuredText changes alone do not qualify; changing CI machinery alone is not a scientific input change. Adding an unrelated registry entry does not qualify existing experiments. Historical registry comparison uses the integrated merge commit's first parent, with exact second-parent head binding; unsupported merge histories or incomplete metadata fail closed. Explicit manual artifact selection remains available for intentional reproductions or other exceptions. Automatic recovery by merged PR uses the same relevance rule; a no-candidate recovery still fails explicitly. This changes archival eligibility, not the experiment selector: documentation can still trigger useful regression CI.

ZIP checks are unchanged: unexpected README.md or any other unapproved file is still rejected, even for a genuine new run. The producer currently uploads the result directory; a real rerun with a tracked README in that directory may still need separate clean-output staging before publication. Do not relax the allowlist or silently discard unknown ZIP entries. Old failed checks remain historical evidence.

## Operator procedure (explicit manual fallback)

1. Review the source artifact contents for publication rights, secrets and sensitive data (including environment package URLs). Only public data may be archived. The script is not a secret scanner.
2. Ensure the original successful Experiments run and its source head commit are integrated into main. Obtain the exact experiment ID, source run ID, artifact ID and full head SHA from GitHub. The artifact must not be expired. Specify all filenames as a comma-separated allowlist.
3. From Actions, select Archive scientific experiment, Run workflow, branch main, enter these values and confirm public archival.
4. The workflow validates source metadata, current and executed-tree registry entries, historical checkout logs and immutable commit/tree identity, successful experiment job, ZIP size/digest/CRC and file allowlist; it copies extracted bytes, including CRLF, into results/ci-originals/<experiment>/<run>-<artifact>/, generates archive-provenance.json and verifies the staged Git blobs. It refuses existing destinations and existing review branch refs. It never replaces canonical results or prior run directories.
5. Review the generated branch and PR. Repository Actions settings must permit GitHub Actions to create pull requests. If PR creation fails, the workflow reports the review branch; create the PR manually. The bot does not post a Codex review command: GitHub Actions bot requests were rejected by Codex account authorization on PR #276 and #281. Request review using the connected user's Repo Autopilot button or an authenticated GitHub comment. GitHub requires approval for pull_request opened/synchronize/reopened workflows triggered with GITHUB_TOKEN (https://docs.github.com/en/actions/concepts/security/github_token). Use Approve and run workflows when requested; verify required CI and Codex before merge. No elevated credential, automatic approval or merge.

## Scope and limitations

Automatic discovery after same-repository merge for opted-in public profiles only; explicit manual dispatch from main remains available. No automatic publication of unprofiled experiments. Supports standard flat JSON/CSV/TXT experiment archives with result.json and the two environment files; special benchmark profiles, nested outputs and binary/GDS/NPZ artifacts require separate audited extensions. Limits: 25 MiB compressed ZIP, 50 MiB expanded, 20 MiB per file, 256 entries. Reject duplicate names (case-insensitive), unsafe paths and nonregular files. For PR runs, the head SHA is not the executed synthetic merge SHA. The exact successful job checkout log must identify the executed commit; its second parent must equal the PR head. The archive records both SHAs, tree SHA and checkout log digest. Missing logs or unavailable historical commit/tree objects stop archival rather than guessing from a current PR merge ref. Dispatch runs require checkout SHA equal to run head. The original ZIP itself is not committed; its published SHA-256 and size plus extracted file hashes are recorded. This verifies integrity and source identity, not scientific correctness, independent reproduction or physical measurements. The experiment workflow must report success; result.json with an explicit false passed flag is rejected. Repository branch protection and human review remain mandatory. Regression tests run in the separate read-only Scientific archive CI workflow on archive implementation or archived-run changes, or manual dispatch. The existing Experiments workflow and dependency selector are unchanged; results changes may still trigger its selector and any genuinely dependent experiment. Live archival was verified by PR #273. Authenticated review remains required; bot-originated requests are deliberately disabled.
