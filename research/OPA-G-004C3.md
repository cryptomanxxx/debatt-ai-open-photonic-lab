## C3B: conditional energy and latency accounting

Unknown terms remain unknown, no zero cost imputation except explicit optimistic sensitivity ceiling. Avoid double counting static source power and per-side dynamic energy. External paper figures require matched operation and boundary before use.

Define E_cpu = common_cpu + N*e_box; E_hybrid = common_hybrid + F*e_box + N*e_pre + S*e_side + E_extra. e_pre is incremental guard/normalization cost averaged per visited node, not only guard outcomes; e_side includes all four operand drives and readout unless itemized separately. E_extra accounts for nonincluded memory, static source/LO power times elapsed time, calibration, transfer and scheduling. Use correct delivered rays as denominator, include all work. Report symbolic break-even and explicitly illustrative grids (e_box 10/100/1000 pJ, e_pre 1/10 pJ, aggregate dynamic side 1/10/100 pJ, static incremental power 0.01/0.1 W, hypothetical side service rate 1e9/s, utilization 0.1/1); additional unknown overhead as remaining budget, not full system energy. Report nonpositive budgets and sensitivity per scene/scenario. If actual calibrated power unavailable, mark energy not measured. No direct comparison with GPU without matched measurement. Latency model must include dependency-driven node scheduling, serialization/parallel lanes, fallback, memory and conversion; no inferred rays/s from modulator bandwidth. Report conditional model separately from actual CPU timing. No FPS or VR headset power claims.
