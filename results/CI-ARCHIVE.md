# Scientific artifact archival

The existing Experiments workflow produces individual CI artifacts and a combined bundle. The new Archive scientific experiment workflow archives one explicitly selected original artifact without rerunning a simulation or copying CSV through chat.

## Operator procedure

1. Review the source artifact contents for publication rights, secrets and sensitive data (including environment package URLs). Only public data may be archived. The script is not a secret scanner.
2. Ensure the original successful Experiments run and its source head commit are integrated into main. Obtain the exact experiment ID, source run ID, artifact ID and full head SHA from GitHub. The artifact must not be expired. Specify all filenames as a comma-separated allowlist.
3. From Actions, select Archive scientific experiment, Run workflow, branch main, enter these values and confirm public archival.
4. The workflow validates source metadata, current and executed-tree registry entries, historical checkout logs and immutable commit/tree identity, successful experiment job, ZIP size/digest/CRC and file allowlist; it copies extracted bytes, including CRLF, into results/ci-originals/<experiment>/<run>-<artifact>/, generates archive-provenance.json and verifies the staged Git blobs. It refuses existing destinations and existing review branch refs. It never replaces canonical results or prior run directories.
5. Review the generated branch and PR. Repository Actions settings must permit GitHub Actions to create pull requests. If PR creation fails, the workflow reports the review branch; create the PR manually. PRs opened using GITHUB_TOKEN may not trigger normal pull_request workflows; a human must ensure required checks actually run (for example, close/reopen the PR or open a human-authored PR from the branch where appropriate). Never bypass branch protection. No automatic merge.

Compare extracted result bytes to canonical OPA-G-003 results and recorded provenance. This will create a separate immutable run archive, not overwrite the manually completed archive. Inspect source package metadata before public confirmation.

## Scope and limitations

Manual dispatch from main only; no automatic publication on experiment completion. Supports standard flat JSON/CSV/TXT experiment archives with result.json and the two environment files; special benchmark profiles, nested outputs and binary/GDS/NPZ artifacts require separate audited extensions. Limits: 25 MiB compressed ZIP, 50 MiB expanded, 20 MiB per file, 256 entries. Reject duplicate names (case-insensitive), unsafe paths and nonregular files. For PR runs, the head SHA is not the executed synthetic merge SHA. The exact successful job checkout log must identify the executed commit; its second parent must equal the PR head. The archive records both SHAs, tree SHA and checkout log digest. Missing logs or unavailable historical commit/tree objects stop archival rather than guessing from a current PR merge ref. Dispatch runs require checkout SHA equal to run head. The original ZIP itself is not committed; its published SHA-256 and size plus extracted file hashes are recorded. This verifies integrity and source identity, not scientific correctness, independent reproduction or physical measurements. The experiment workflow must report success; result.json with an explicit false passed flag is rejected. Repository branch protection and human review remain mandatory. Regression tests run in the separate read-only Scientific archive CI workflow on archive implementation or archived-run changes, or manual dispatch. The existing Experiments workflow and dependency selector are unchanged; results changes may still trigger its selector and any genuinely dependent experiment. The live archive dispatch has not yet been tested.
