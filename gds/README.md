# GDS archive

Frozen copies of chip layouts (GDS files) that the lab has released: sent to
someone, submitted for review, or kept as a milestone. The working layouts are
generated by the scripts in [`layout/`](../layout/) and change over time; a
release here **never changes** after it is added, so it is always possible to
show exactly which file was shared and when.

## Layout

One folder per release, named `<design>-<version>[-<recipient>]`:

```
gds/
  opa-mzi-2x2-v1-example/
    programmable_mzi_2x2.gds      the file exactly as released
    provenance.json               where it came from (required)
    README.md                     optional short description
```

## `provenance.json`

Required in every release folder. [`tools/check_gds_archive.py`](../tools/check_gds_archive.py)
checks it in CI (workflow `gds-archive.yml`).

```json
{
  "design": "Programmable 2x2 MZI",
  "version": "1",
  "date": "2026-11-10",
  "status": "exploratory",
  "pdk": "gdsfactory generic PDK",
  "generator": {
    "script": "layout/mzi_2x2_layout_v001.py",
    "commit": "8be28fe62c00676bd6543d9d3e0a62ada9420f2f",
    "environment": "layout/requirements-lock.txt"
  },
  "released_to": "nobody yet",
  "files": {
    "programmable_mzi_2x2.gds": "sha256 of the file"
  },
  "notes": "Not DRC-checked against any foundry rules."
}
```

| Field | Meaning |
|-------|---------|
| `status` | One of `exploratory`, `drc-clean`, `submitted`, `fabricated`. Only use `drc-clean` once the foundry's own DRC deck has passed. |
| `pdk` | The process design kit the layout targets. |
| `generator` | The script, commit and locked environment that produce the file, so the release can be regenerated. A release without a generator in this repository is not reproducible and should say so in `notes`. |
| `released_to` | Who received it, for example a foundry, a review programme or a collaborator. |
| `files` | The SHA-256 checksum of every GDS file in the folder. CI fails if a file is changed, added without a checksum, or missing. |

## Releases

None yet. The current working layout is
[OPA-LAYOUT-001](../results/opa-layout-001/) (programmable 2×2 MZI, generic
PDK, 23.0 µm couplers), which is regenerated and checked by CI on every change.

To add a release:

1. Generate the GDS with the layout script at a committed state.
2. Copy it into a new folder here and write `provenance.json`, using
   `sha256sum <file>` for the checksum.
3. Run `python tools/check_gds_archive.py` and open a pull request.
4. Add a row to the table above.

Publishing a layout here makes it public. Check that the PDK's licence allows
sharing layouts that use its cells before adding a release that targets a
foundry PDK.
