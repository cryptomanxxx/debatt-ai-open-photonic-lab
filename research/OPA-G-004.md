# OPA-G-004 — Matched electronic and conditional photonic ray-box benchmark

Protocol with G-004A/B/B2 executed and archived; no measured optical hardware result. G-003B [archived analysis](../results/opa-g-003b/README.md) closes the numerical stress experiment but does not establish a robust optical decision policy. Do not advance to physical integration on this evidence alone.

## G-004A: electronic reference and workload freeze

Reuse G-001 exact rational face oracle and G-002 corrected determinant. Define one operation as one complete forward-ray/closed AABB classification, not one optical side or one MAC. Freeze represented inputs, seeds, ray/box IDs, array layout, hit/miss labels and hashes before timing; use identical pairs and output ordering for each method. Include uniform and translated/variable-size boxes, G-003B-like boundary stress as a separate panel, parallel/inside/behind/degenerate cases, and a distinct held-out scene-like ray/box workload (not a validated production distribution). Separate calibration, development and held-out evaluation. Include varying batch sizes and record active axis, electronic guards and side-test counts.

First implement a vectorized float64 slab CPU baseline, an independent optimized compiled CPU baseline where available, and optional actual GPU kernels (same represented inputs and output semantics). Compare each against oracle, record FP/FN separately per panel; do not time the rational oracle as the optimized electronic baseline. FP32 or reduced precision must be classified on the same original represented inputs; separately record input rounding. GPU unavailable => explicitly not run, no invented timing or CPU-emulated GPU result. Record device, software versions, threads, precision, warmup, synchronization, memory residency and repetitions. Report throughput in ray-box tests/s and batch p50/p95 latency (not individual ray latency); distinguish resident kernel from host-inclusive transfer and allocation. Keep noisy shared CI timing descriptive, never an acceptance gate for speed.

## G-004B: frozen accuracy and accounting

Reuse G-003 optical model and G-003B confidence logic without changing historical scripts. Freeze candidate windows using calibration only; compare any-side, min-window, pure electronic and all-fallback controls on identical held-out geometry and paired noise. Include preprocessing and input quantization as separate stages. Report absolute FP and FN, conditional rates (undefined if denominator zero), raw/after-fallback counts, guard/optical/fallback fractions, and correctly delivered results. Provisional strict matched-quality screen: zero observed FP and FN in every held-out panel and repeat for both compared methods, including stress; not a statistical guarantee or application requirement. Report all failures and denominators; no ranking of unmatched settings. A fully electronic fallback is a correctness reference, not evidence for photonic benefit. Track guard and fallback costs, and if exact oracle fallback is used, explicitly label optimistic correctness and unknown implementation cost until a realizable electronic fallback is validated. Do not assume fallback uses a free exact oracle.

Reuse the accounting discipline of [CIR008](OPA-CIR-008.md) and [CIR final report](OPA-CIR-FINAL-REPORT.md), not their numerical MVM component counts. Record separate optical-core, accelerator-card and host-inclusive boundaries. Count 4 driven MZM operands per side test under the serial-pair model; two product paths, coherent reference and balanced receiver; actual lane reuse, pipelining, comparator topology and source allocation remain assumptions. Count all active side tests (2 for two active axes, 6 for three), and do not credit side early termination unless implemented and measured or explicitly modeled. Include normalization/guard arithmetic, input DAC and drivers, laser and LO wall-plug power with loss and fanout, balanced photodetectors/TIA, two threshold comparisons per side or equivalent digitization, digital aggregation, calibration/tuning, clocks/idle, BVH/ray memory traffic, DMA/host transfer and fallback. Document units, reference planes, active vs static energy and avoid double counting. Unknown terms remain unknown; partial budgets cannot be ranked as full systems.

Report energy per delivered correct ray-box test = total energy over the declared batch boundary / (N-FP-FN), undefined if zero correct; include failed tests and fallback work in numerator. Latency and throughput require resource and scheduling assumptions, not merely modulator bandwidth. Provide symbolic break-even cost and sensitivity to fallback, side count, utilization, memory and conversion energy; separate measured electronic values, external source data and illustrative assumptions. If actual GPU/CPU energy instrumentation is unavailable, mark energy unmeasured; power×time estimates with explicit boundaries are conditional only. No conversion of 326 fJ/operation from Zhang et al. to ray-box energy without reconstructing the operation and boundary. No FPS, headset power, GPU superiority or fabrication claims.

## G-004C: BVH traversal extension

Only after a matched pairwise baseline, freeze common BVH, rays, traversal order and triangle intersection reference. Compare visited node count, missed hits, extra traversal, final nearest-hit identity/distance and workload-level time/energy with same quality. False positives may add traversal; false negatives may omit geometry. Do not extrapolate pairwise speed to frame rate. GPU access and power measurement are open requirements. Publish raw results, environment and CI provenance; preserve failed cases. Existing CIR/LIB and fabrication priorities unchanged.
