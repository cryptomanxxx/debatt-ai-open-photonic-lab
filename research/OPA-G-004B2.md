Preserve uniform, translated, scene-like and dyadic boundary panels, and add explicit near-parallel and large dynamic-range stress panels. Report distribution and guard counts separately; do not treat repeated noise as independent geometry. Validate compiled FP64 fallback against exact labels before use; if it fails, do not credit it as a matched-quality reference on that panel. Maintain separate original G-004A/B archives. Reuse existing optics, CPU and exact geometry helpers, not new component layouts.

Preregister candidate policies before opening the new heldout results: the existing calibration max-min window; max-min multiplied by fixed factors 1.25, 1.5 and 2; a calibration-side maximum-residual window; electronic-only and all-optical fallback controls. No scenario-dependent deployment selector unless independent observables are explicitly modeled and validated. Fit gain/offset on calibration only; choose at most one nontrivial candidate on development across all scenarios using zero FP/FN and minimum worst-scenario fallback, with deterministic tie order from the listed candidates. If none qualifies, report no candidate rather than retune heldout. Report every candidate as diagnostic, but only the frozen selected candidate is eligible for a prospective confirmation claim. Use new independently seeded static biases and receiver noise, separate calibration and test draws; include fixed G-004B scenarios and an explicitly hypothetical drift/quantization stress with stated amplitudes before execution. Repeat at least ten times; retain scenario/panel/repeat counts and selected thresholds. Quantization must use identical original represented inputs as reference; separate input rounding from optical error.

Gate: zero observed FP/FN on every fresh heldout panel/repeat/scenario, and some optical decisions without fallback in every scenario. This is finite-sample evidence, not a safety guarantee. Report worst-panel fallback even when gate passes; no energy ranking if quality fails. Conditional overhead budgets only; actual conversion, laser/LO, memory, aggregation, calibration, host and cooling remain unmeasured. Use compiled CPU rather than NumPy as primary electronic comparator. No GPU or optical speed claim.
