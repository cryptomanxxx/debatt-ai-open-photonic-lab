# OPA-G-004A — Electronic reference and frozen workloads

Implementation of [G-004 protocol](OPA-G-004.md). One test means one complete forward-ray / closed AABB classification. Reuse G-001 rational face oracle, G-002 exact side test and G-003B geometry generator and exact guard audit; no optical benchmark in this stage.

## Frozen workloads

Three disjoint partitions (calibration/development/heldout, seeds 20261201/02/03). Each has four panels: 2048 uniform, 2048 translated variable-size (including degenerate widths), 1664 signed boundary cases (seed +100), 2048 scene-like pairs (64 camera rays × 32 shared boxes). Remove duplicate represented pairs within/across panels and partitions in fixed generation order; record generated and retained counts. Scene-like pairs are correlated synthetic data, not a validated production workload. No BVH traversal. Explicit parallel, behind, inside, stationary, negative direction, tangent, near-miss and degenerate controls are separate untimed gates. IDs are the tuple (split,panel,pair_id); ray and box coordinates are stored per pair, not separate scene object IDs. Exact input/label hashes and complete CSV with round-trip verification precede timing; manifest identifies little-endian float64 layout and CSV hash. Reuse the archived workload rather than regenerate it for future comparisons.

## CPU methods and timing

Vectorized NumPy float64 slab, float32 variant and independent compiled C double slab (cc -O3, no fast-math, no fused contraction, scalar source, single calling thread). Missing compiler is recorded as not run; compilation failures fail CI rather than silently hide a problem. No GPU backend is configured; GPU and energy explicitly unmeasured. Accuracy evaluated against the original exact labels, and FP32 input rounding isolated with an exact oracle on rounded inputs. Report conditional FP/FN rates and separate rounding/arithmetic counts; no accuracy threshold enforced on finite precision beyond explicit float64 control cases. Guards and side counts are exact theoretical optical work counts, not measured CPU work. Oracle never timed.

Held-out resident contiguous inputs only; 32, 256, 1024 and full-panel prefixes, three warmups and 21 individually timed repetitions per method/batch. Timing includes Python dispatch, output allocation, NumPy temporary arrays or ctypes call overhead. No transfer or disk time; not a pure compiled-kernel benchmark. Each timed output is checked against the corresponding untimed result after stopping the clock. Report raw ns samples, batch p50/p95 and batch-size/p50 throughput; method order fixed and shared CI scheduling/caches may bias timing. CPU model, affinity, software, compiler flags and thread environment recorded. No speed gate, no GPU emulation, no optical speed/energy claims. Future controlled dedicated benchmarks should randomize method order, repeat across processes and measure transfer/energy separately.
